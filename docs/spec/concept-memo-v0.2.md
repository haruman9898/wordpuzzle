作成: 2026-11-26（v0.1 からの改訂点: §2「面白さの核」をユーザーの指摘で全面差し替え、それに合わせて §5〜§7 を調整）

## 1. コンセプト [ユーザー案]

アルファベットは、より小さな「形のパーツ」の組み合わせでできている、という発想のパズル。

- A = V + I（横棒）、P = I + C、W = V + V のように、各文字には分解式がある
- お題の英単語が出る
- 画面上にパーツが散りばめられる
- パーツをタップして選び、各文字の枠（スロット）にはめる
- 全スロットが埋まると単語が完成する

類似ゲーム調査（2026-11-26）: この形そのままのゲームは見つからなかった。近いものは子ども向け文字パーツジグソー（専用ピース・1文字ずつ）、印刷教材 DIY Letters（汎用ピースで全文字）、Word Factori（i から文字を作る工場ゲーム）。差別化の核は「汎用パーツの共有プール × 単語単位の完成」。

## 2. 目指す遊び心地 [ユーザー指摘で確定]

v0.1 で挙げた「式の発見・配分の迷い」は主役ではない。目指すのは次のようなお手軽さ。

1. **単純なルール**: 出されたお題に当てはまるパーツを、軽快に選んで当てはめていくだけ。
2. **深く考えない**: 深い思考は不要。脳トレ＋暇つぶしとして、これだけに集中できる。気づいたら夢中で時間が経っている状態が理想。
3. **はめる爽快感**: ピースが当てはまった時の音と振動。単語が完成した時の演出と音・振動による大きな爽快感。

参考タイトル（App Store 上位のカジュアルパズル）:
- ArrowCube - 3DPuzzle: 矢印を順にタップして取り除くだけの単純ルール。外れる時の連鎖と手触り。
- ブロックブラスト（Block Blast）: 自称「脳トレ＆暇つぶし」。ブロックが弾ける演出と心地よい音、コンボ、失敗を気にせず続けられる設計。
- スキュアジャム（Skewer Jam）: 時間制限なし・焦りなし。仕分けて揃えていく作業感と「すっきり片づく瞬間」の気持ちよさ。

3作の共通項 = ルールは一目で分かる／1アクションごとに小さな気持ちよさが返る／失敗の圧が低い／次の1問がすぐ始まる。

## 3. パーツシステム [決定]

- 分解表 v0.6 が正: `parts-table-v0.6.md`
- パーツは9種: I（直線）、C（半円カーブ）、V（角）、L（直角コーナー）、D型、O型、P型、F型、J型
- パーツ名は形の名前。大きさ・回転・反転は、はめる枠に合わせる
- 全26文字・合計49パーツ。1個で作れる文字が5（C, I, J, L, V）、2個が19文字、3個は H と M だけ
- S字パーツは使わない（S = C + C）
- 見本ページ（Space: aruhuabetutofen-jie-pazuru-jian-ben）で全文字の見た目を確認済み。ユーザーが「イメージ通り」と承認（2026-11-26）。D と P の見分けも問題なし
- 見本の文字形状はその後 B・P・R の縦長と S の不成立を修正し、曲線の膨らみも拡大（2026-11-26）。ユーザーの評価は「まあまあ」で、見本はあくまで参考資料という位置づけ
- **実装時の引き継ぎ指示 [決定]**: 実装は Claude Code に依頼する予定。その際「この見本通りに実装するのではなく、あくまで参考としてください。縦横バランスを調整して、見やすいバランスで文字が表示されるように実装してください」と伝えること
- 分解式の共有（V+I が A・N・Y・Z を兼ねる等）は、システムとして気持ちよさを支える土台ではあるが、プレイヤーに「考えさせる」要素として押し出さない [v0.2 で位置づけ変更]

## 4. 基本の流れ [決定 2026-11-27: ステージ制＋制限時間を採用]

1ステージ = 決まった数のワードを、制限時間内に全部完成させる。

1. ステージ開始と同時に、残り時間のカウントダウンが始まる
2. お題の単語が表示される（文字の輪郭だけが見える状態）[提案]
3. その単語に必要なパーツが画面に散りばめられる
4. パーツをドラッグして枠まで運び、離すとはまる（音＋軽い振動）[§5]。[決定 2026-11-26: 操作はドラッグのみ。タップ選択は使わない。当初のタップ案から変更]
   - 掴んだパーツは指で隠れないよう、指の少し上に浮かせて表示する
   - 合う枠に近づくと吸着（スナップ）する
   - 合わない枠では軽く弾かれるだけ。パーツが勝手に即座に戻る動きは不採用で、プレイヤーが指を離した時点で元の場所に戻っていく（ペナルティなし）[決定 2026-11-28、§7-3]
5. 正しいパーツは固定され、文字が1つずつ完成していく（文字が完成した瞬間にも小さな演出）
6. 単語が完成したら大きな演出 → 間を置かず次の単語へ。完成ごとに制限時間へ +2秒のボーナス [提案]
7. 制限時間内に全ワード完成でステージクリア。時間切れは失敗で、その場ですぐ再挑戦できる（ペナルティなし）[提案]

## 5. 演出・音・振動 [v0.2 で新設、ユーザーの核要望]

このゲームの商品価値の中心。仕様として最初から作り込む。

- **はめた瞬間**: 短く気持ちいい「ポコッ」という音＋軽い振動（ハプティクス）。連続ではめると音程が少しずつ上がる [提案]
- **文字が1つ完成**: 小さな跳ね・光るアニメーション＋一音高い音 [提案]
- **単語が完成**: 画面全体の祝福演出（文字が順に跳ねる、紙吹雪など）＋完成ジングル＋しっかりした振動 [ユーザーの核要望]
- **間違えた時**: ペナルティなし。軽く弾かれる動きと鈍くない音で「そこじゃない」だけ伝える [提案、§2 の低圧方針から]
- **残り時間わずか**: 残り10秒以下でタイマー表示が赤くなり、軽い警告音で焦りを演出する [提案、ステージ制に伴い追加]
- **ステージクリア／失敗**: クリア時は大きめのジングル＋演出、失敗時は短く控えめな音で、すぐに再挑戦へ気持ちを切り替えさせる [提案、ステージ制に伴い追加]
- **BGM**: 主張しすぎない軽いループ。ミュート切り替えあり [提案]
- ブラウザ実装での振動は端末・ブラウザ依存（iPhone Safari では制限あり）。試作段階で実機確認する [注意点]

## 6. ステージと難易度 [決定 2026-11-27: ユーザー提案のステージ制]

難易度は「ワード数 × ワードの文字数（総パーツ数）」で上げる。制限時間はワード数と難易度に応じて調整する。

進行の目安 [ステージ1の規模はユーザー指定 2026-11-27: 2ワード・2文字くらいから始めるのがちょうど良い]:
- ステージ1: 2ワード × 2文字（総パーツ約8）→ 20秒
- ステージ2: 3ワード × 3文字（総パーツ約16）→ 30秒
- ステージ3: 3ワード × 3〜4文字 → 35秒
- ステージ4: 4ワード × 4文字 → 45秒
- ステージ5: 4ワード × 4〜5文字 → 50秒
- ステージ6: 5ワード × 5文字 → 60秒

制限時間の算出式 [提案]: 総パーツ数 × 約1.7秒 ＋ ワード数 × 2秒 を目安にし、5秒単位に丸める。この式があればステージを自動生成・量産できる。
お邪魔パーツ [決定 2026-11-28、§7-2]: プレイに慣れてきた頃のステージから登場させ、難易度に応じて数を増やしていく。
クリア評価 [決定 2026-11-28、§7-4]: クリアタイムに応じて⭐︎1〜3でステージを評価する（⭐︎3 = すごく良いタイム）。各星のタイム境界は仕様書でステージごとに決める。
単語ごとの総パーツ数の例: CAT=5、DOG=6、JUNE=7、WORD=8、GAME=9、PUZZLE=11。
お題の単語プール: 身近な英単語（動物・食べ物・身の回りのもの）から [提案]。カテゴリ分けするかは [未決定]。
（旧方針「時間制限なし・失敗なし」はこのステージ制の採用で置き換え。ただし失敗時の圧は低く保つ: 即リトライ可・ペナルティなし）

## 7. 検討事項と決定（2026-11-28 にユーザーが各項目を決定）

1. **回転・反転**: [決定 2026-11-28] 自動。プレイヤーは当てはまるパーツをドラッグして移動させるだけ
2. **お邪魔パーツ（ダミー）**: [決定] 入れる。プレイヤーがプレイに慣れてきた頃のステージから登場させ、難易度に応じてどんどん増やしていく
3. **間違えたときの扱い**: [決定] 合わない枠では軽く弾かれる動きだけ。「はまらない→即座に元の場所に戻る」動きは不採用。プレイヤーが指を離すと、パーツは元の場所に戻っていく。ペナルティなし
4. **評価の仕組み**: [決定] クリアタイムに応じて⭐︎3つでステージ評価を表す。⭐︎3 = すごく良いタイム（各星の境界タイムは仕様書で決める）
5. **ヒント**: [決定] 一定時間操作が無ければ、当てはまるパーツが小刻みに震える演出を入れる。プレイヤーは次に動かすべきピースが分かるようになる（震え始めるまでの秒数は仕様書で決める）
6. **複合パーツの別解**: [決定] 形が合えば良い（別解を認める）
7. **タイトル**: [未決定]
8. **プラットフォームと分担**: [決定] まずはスマホブラウザ（縦画面）。その後アプリ化を希望する。企画・仕様・レビュー = Muse、実装 = Claude Code
