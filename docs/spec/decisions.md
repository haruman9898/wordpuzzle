# 決定事項ログ（Claude Code 側）

Muse が書いた仕様書 v0.1 と試作指示書に対する、ユーザーの承認事項。仕様書の更新は Muse の担当なので、v0.2 に反映するための記録。
最終更新: 2026-11-28

## 仕様の穴の補足（承認済み）
1. **別解の扱い（試作）**: 同じ型のパーツどうしの入れ替えだけを許す。複合パーツ（D・O・P・F・L）による別解は本実装に回す。
   - 枠ごとの許容パーツ一覧（accept set）をデータとして持つ。
2. **出題の制御**: ステージごとに、引いた単語の総パーツ数が一定の帯に収まるようにする（運で難易度が変わらないようにする）。
3. **星の判定**: ボーナス（+2秒）を除いた、実際にかかったクリアタイムで判定する。
4. **プールのパーツの見せ方**: 定数 `POOL_ORIENTATION: 'canonical' | 'matched'` で切り替えられるようにし、実機で比べる。

## 追加する要素（承認済み）
- 開発用パネル（定数を画面上で調整）とプレイログ（1パーツあたりの平均はめ時間・失敗回数を、コピーできるテキストで出す）
- 左上に FPS・振動対応・音の状態の診断表示
- チュートリアル（ステージ1の最初の単語で、指のゴーストがドラッグして見せる。文字の説明は入れない）
- コンボ表示と「パーフェクト」（ミスなしで単語を完成）
- リトライ時は、同じ難易度帯の別単語を出す
- `localStorage` の読み書きを try/catch で守る
- コインが降ってくる演出（単語完成時。紙吹雪の代わり）。画面隅の瓶に溜まる。1単語 = 5枚、合計をブラウザに保存、結果画面に獲得枚数を表示。使い道は本実装で決める。

## 実装で決めた細部（手触り確認版 proto1-a、2026-11-28）
- **ミスの定義**: 合わない型の枠の上で離したら「ミス」（コンボが途切れ、PERFECT にならない）。何もない所で離した場合や、はまらずに元へ戻っただけの場合はミスにしない。
- **合わない枠の演出**: 近づくと軽く揺れて短い音が鳴る。ただし指の下からパーツを動かしはしない（元の場所へ戻るのは離した時だけ）。
- **別解**: 同じ型のパーツは、どの枠にも入る（A の横棒の枠に T の縦棒の I を入れるなど）。吸着中は、枠の形（自動で回転・拡大縮小した形）に切り替えて見せる。
- **パーツの掴み方**: 線までの距離で判定する（見た目より広い当たり判定）。ドラッグ中は、指の上 `DRAG_OFFSET_Y` px にパーツの中心を浮かせる（約 0.1 秒かけて移る）。
- **文字の幅**: 文字ごとに、形の幅 + 線の太さ + 余白 16 で決める（I は細く、W は広い）。
- **ヒント / ゴースト**: ヒントは操作（はめる・離す）から `HINT_DELAY_SEC` 秒後。初回プレイだけ、指のゴーストが最初のパーツをドラッグして見せる（最初に1つはめると消え、以後は出ない）。
- **POOL_ORIENTATION**: `matched`（枠と同じ形）と `canonical`（型ごとの標準形）の両方を実装。開発メニューで切り替える。
- **振動**: Android などは `navigator.vibrate`、iPhone は `<input type="checkbox" switch>` のクリックを、pointerup の中で同期的に発火する（要実機確認）。
- **キャッシュ**: iPhone の強いキャッシュ対策として、ES モジュールは使わず、`?v=BUILD` 付きの通常の script にする。ファイルを変えたら `index.html` の `proto1-a` を全て新しい値に置き換える。画面左上の BUILD で、読み込まれた版を確認できる。

## 振動の調査（proto1-b、2026-11-28）
- proto1-a の実機テストで、iPhone では振動が出なかった（ユーザー報告）。
- iPhone の回避策（switch のクリック）を4方式に分け、開発メニューで切り替えて試せるようにした。掴んだ瞬間にも軽い振動を出す設定（`HAPTIC_ON_GRAB`）を実験として追加した（仕様書の表にはない。要否は試遊で決める）。
- Android の Chrome は `navigator.vibrate` で動くはず（未確認）。
- どの方式でも iPhone で出ない場合は、アプリ化（ネイティブの触覚）まで振動は見送る。

## proto2（ステージ構造・演出・音・見た目、2026-11-28）で決めた細部
採用済み: 演出の強化、ステージ構造（タイマー・星・結果）、場面の切り替え、音の作り込みと BGM、見た目の質感、ヒントの強化、レイアウト調整。不採用: ホーム画面への追加（PWA）。

仕様書にない解釈（Muse の確認が必要）:
- **タイマーの開始と停止**: 単語のパーツが飛んできて着地した時に動き出す。単語完成の演出・切り替えの間は止まる（待ち時間は制限時間にも星の判定にも含めない）。ステージ開始の「STAGE n」表示の間も動かない。
- **+2秒ボーナス**: 最後の単語以外で、単語を完成するごとに加算する（`BONUS_SECONDS`、0 にもできる）。
- **星の判定**: 「実際に遊んでいた時間」（ボーナス・待ち時間を除く）を、仕様書の表から換算した秒数と比べる。ステージ1は 13秒以内 = ⭐3、17秒以内 = ⭐2、それ以外 = ⭐1。ステージ2は 20/25 秒、ステージ3は 23/30 秒。
- **出題**: 各ステージで、単語の総パーツ数が範囲に収まる組み合わせだけから選ぶ。ステージ1 = 6〜8、ステージ2 = 15〜17、ステージ3 = 19〜23（ステージ3は4文字の単語を最低1つ含める）。同じステージの中で単語は重複しない。リトライでは、直前と別の単語を優先する。各範囲に収まる組み合わせがあることを、200回の抽選で確認している。
- **失敗**: 結果画面は挟まず、「TIME UP」の短い表示から、すぐ「もう一回」に進める（仕様書 §2 の趣旨）。
- **ステージ3のあと**: ステージ4がまだないため、「ここまでが試作です」と表示し、「次のステージ」は出さない。
- **進行（⭐の保存）**: ステージ1だけ最初から選べ、前のステージを1つ以上の⭐でクリアすると次が開く。保存は `localStorage`。
- **一時停止**: ボタンで止まる。アプリが裏に回った時、開発メニューを開いた時も自動で止まる。
- **進捗ドット**: 仕様書 §3 のとおり残す。コインの瓶は、その横に置く。
- **BGM**: 既定はオン、音量 0.6。ミュートとは別に切れる（開発メニュー）。静かな生成ループで、ステージ中だけ流れる。
- **チュートリアル**: 初回プレイの最初の1つだけ。
- **ヒント**: 震えるパーツに加えて、はまる枠も脈打つ。
- **レイアウト**: 2文字の単語は大きく見せる。パーツ置き場に重ならず収まるか事前に試し、収まらなければ全体を縮める。
- **フリープレイ**: タイマーなしで単語だけ遊べるモードは、開発メニュー専用（動作確認用）。ゲームの機能としては出さない（無制限モードは不採用のまま）。

## proto2-a の試遊結果（2026-11-28、ユーザー報告）
- **制限時間**: 緩い。ただしステージ序盤なので、今のままで良い（調整しない）。
- **音・演出**: 良い。
- **文字・パーツのデザイン**: 一つ前（proto1）のほうが良い → proto2 で足した「つや」（白いハイライト線）を既定でオフにした（proto2-b）。開発メニューの「パーツのつや」で戻せる。文字枠の後ろのカードは残した（「文字枠のカード」でオフにできる。好みで判断する）。
- **振動**: iPhone（iOS 18.7）では出なかった。診断表示は `ios-switch/label-onscreen`。他の方式と「本物のスイッチ」の結果は未確認。
- **実機ログ**: 画面 393×641 で、FPS 60（最小 47、最悪フレーム 48ms）。平均はめ時間は 580〜2000ms（慣れると 700ms 前後）。16単語、ミス 1回。

## 振動の調査（続き、proto2-c、2026-11-28）
- 実機（iPhone、UA は iOS 18_7）で、「本物のスイッチ」を指で直接タップすると振動する。コードからの `label.click()`（label-onscreen）では出ない。
- 調べた範囲では、switch の触覚をコードから出す方法が iOS 26.5 で塞がれたという情報がある（第三者の記述で、公式には未確認）。UA の OS バージョンは、実際より古く表示されることがあるため、端末の iOS が 26.5 以降の可能性がある。
- 原因を絞る実験メニューを追加した（場面 A〜H × 方式）。`ondemand`（毎回 label を作る方式）と、はめた時の振動を `touchend` まで遅らせる設定も追加した。
- 全部だめな場合: アプリ化の時に、iPhone 本物の触覚を使う（Web 版では、効果音と演出で成立させる）。

## 振動の調査の結論（2026-11-28、実機の実験結果）
- 実機（iPhone）の実験: 「透明な label を、指で直接タップする」（G）だけが、小さく振動した。コードから `label.click()` を呼ぶ方式（A〜F・H。ondemand と label-onscreen の両方）は、場面を変えても、すべて無反応だった。
- 結論: この iPhone の Safari では、コードから触覚を出せない。**ゲーム中の「はまる」「単語完成」の振動は、Web 版では出せない**（ドラッグして離す動きは、タップではないため、直接タップ方式も使えない）。
- 使える可能性があるもの: 指で本当にタップするボタン（タイトル・ステージ選択・結果画面・一時停止など）は、`<label>` に変えれば、タップ時に小さな振動を付けられる。
- ゲーム中の振動は、アプリ化（ネイティブの触覚）の時に実現する。Web 版では、効果音と演出で成立させる。
